# HR Hive — инструкции для Codex

Работайте из корня репозитория в VS Code на macOS или Windows. Команды обработки выполняйте в Docker:
`docker compose run --rm app COMMAND`. Авторизация Codex остаётся на компьютере пользователя.
Не открывайте рабочие SQLite-базы через Python/sqlite3 на хосте: доступ к базе,
включая чтение и проверки, выполняйте только внутри Docker. На общем bind mount
смешанный доступ с хоста и из контейнера может повредить WAL. Во время `retry`
дождитесь завершения извлечения перед `claim`/`submit`/`export`.

## Сначала

1. Прочитайте `rules/accepted_rules.md` полностью.
2. Выполните `status --all`. Активный запуск указан в `data/state/active.json`.
3. Источники активной версии: `data/state/runs/<run>/inputs/`; история старых запусков: `data/state/history/`. Критерии и бан-листы не находятся в GitHub.
4. Не запускайте старые скрипты из history: они содержат прежние пути, устаревшую классификацию и разовые исправления.

## Продолжение

* Для отдельного архива используйте `import-archive --file ... --template ... --output ...`, затем `extract --workers 2`. Это новый запуск только для ID архива, без переноса прежних оценок. Шаблон из 38 колонок использует ID в A; шесть новых колонок добавляются справа, незавершённые строки включаются со статусом.
* При разрешённой пользователем параллельной работе один координатор обращается к SQLite и выполняет `tools.batch_coordinator packet`/`save-ready` в Docker. Помощники читают все части пакетов и сохраняют по одной карточке атомарно в `runs/<run>/cards/<worker>/<ID>.jsonl`; завершение записи обозначается переименованием временного файла. Помощники не выполняют команды базы или экспорта. Для «100 Лидеров» не используйте устаревший профиль N003: результат строится только из двух независимых направлений.
  Карточка помощника дополнительно содержит `read_parts: [[offset,end],...]` для всех частей пакета и `read_files: [path,...]` для всех его оригиналов в исходном порядке. Координатор проверяет эти подтверждения до preview/submit.

* `scan` обнаруживает новые/изменённые CV в `data/cvs`, сохраняя завершённые результаты отсутствующих оригиналов. Если исходники критериев изменены, используйте `scan --new-version`; полные тексты сохраняются, оценки пересматриваются.
* `extract` читает новые документы; `retry --ids ID ...` повторяет проблемные. Не заменяйте нечитаемый ID следующим и не отмечайте его обработанным.
* Если проверка выявила отсутствующие страницы, обрезанный исходник или посторонний документ вместо CV, координатор сохраняет отчёт с ID, путём/SHA файла, хешем текста, `full_text_review_complete:false` и конкретной причиной; затем `reject-source --id ID --worker WORKER --file /data/.../report.json`. Подтверждение просмотра — `source_visual_review_complete:true`; для полностью прочитанного текстового документа допустимы `source_document_review_complete:true` и полные `read_parts`/`read_files`. Кандидат остаётся незавершённым, причина попадает в Excel; повторное OCR того же хеша не снимает блокировку. Завершённые результаты эта команда не меняет.
  Если файл полный, но относится к другому человеку и корректно используется под другим ID, укажите в отчёте `scope: "candidate"`: блокируется комплект файлов только этого кандидата в текущем запуске. Общий SHA такого документа не блокируется; повторное извлечение и сохранение конфликтного комплекта всё равно запрещены.
* `profiles` показывает актуальные заполненные профили и виртуальные дополнения. Читайте требования, не только название.
* `claim --worker codex --count 5` возобновляет закреплённые незавершённые ID или выдаёт следующий пакет.
* `show --id ID --offset 0 --limit 10000` выдаёт текст и `next_offset`. Пока next_offset не null, читайте следующую часть. Не ограничивайтесь первым фрагментом. Сверьте все файлы одного ID и полную трудовую историю, при сомнении откройте оригинал/страницы. Показ текста сохраняет интервалы чтения; submit отвергает неполный показ.
* Сохраните карточку UTF-8 в `data/state/cards/<ID>.jsonl`. Не передавайте кириллицу через несовместимую кодировку терминала. Предпочитайте редактирование файла.
* `preview --worker codex --file /data/state/cards/<ID>.jsonl` проверяет факты, цитаты, баны и баллы. Проверьте неожиданное исключение профиля или бан по источнику; не подгоняйте карточку под желаемый ответ.
* `submit --worker codex --file /data/state/cards/<ID>.jsonl` транзакционно сохраняет один результат. После каждого кандидата отправляйте карточку. В конце пакета обязательно `export`: это и штатная остановка, и восстановление книги после сбоя.
* Комментарии только конкретные русские; не заменять потерянные данные общей фразой. Неизвестные сведения не додумывать.

## Карточка

```json
{
  "id": "ID",
  "name": "ФИО кандидата",
  "phones": [],
  "education": "Подтверждённая квалификация",
  "jobs": [["Работодатель", "2023-01", "2024-03", "Должность и фактические задачи", "Подтверждённый регион", "private"]],
  "tracks": {"mechanical_design": ["middle", 2, "Дословная цитата из CV", "Подтверждённые задачи и инструменты"]},
  "reviews": [["N240", [34, 24, 15, 10], "mechanical_design", "Конкретные основания оценки", "Существенный неподтверждённый навык"]],
  "exclusions": [],
  "comment": "Краткое существенное пояснение",
  "reviewed_text_sha256": "Хеш из show",
  "full_text_review_complete": true
}
```

Тип организации: `private`, `public`, `public_edu`, `private_edu`, `edu_unknown`, `public_med`, `private_med`, `med_unknown`, `security_public`, `military`, `unknown`. Не делайте организацию государственной по общему описанию отрасли. Регион не выводите из места жительства кандидата.

Все jobs имеют минимум шесть полей; `present` означает продолжающуюся работу, пустая дата — неизвестную. Неполные YYYY/YYYY-MM допустимы. Для спорной занятости с применимым запретом возможен седьмой объект `{"employment_uncertain":"Причина"}`.

Профессиональные семейства КБ: `mechanical_design`, `mechanical_technology`, `chemical_technology`, `cnc`, `electronics`, `embedded`, `rf`, `aerodynamics`, `metallurgy`, `hardware_test`, `software_engineering`, `industrial_engineering`, `fpga`, `electronics_engineering`, `aerospace_engineering`. Используйте семейство по подтверждённой работе. В остальных кластерах — осмысленный идентификатор специализации.

`pedagogy: true` — только подтверждённая педагогическая квалификация; `construction_work: true` — только реальные строительные работы; `business_results: true` — только конкретные результаты бизнеса/предприятия. `independent_directions: [["family1"],["family2"]]` — для двух независимых профессий. Не ставьте флаги ради прохождения валидатора.
Для «100 Лидеров» движок сам умножает базовую оценку на 1,15 до ранжирования
(округление 0,5 вверх, максимум 100). В карточке указывайте исходные баллы
профилей; повторно применять коэффициент вручную не нужно.

Для банов храните дословную цитату через `ban_quote_anchors` по схеме `app/engine/pilot150_evidence.py`. Отсутствие цитаты не повод отключить проверку. При бане можно не оценивать профессии, но фактический разбор всех работодателей обязателен.

Не ищите кандидатов в интернете и не отправляйте CV во внешние сервисы. Локальный OCR не использует API. Не учитывайте возраст, пол и другие личные признаки. Не делегируйте работу другим агентам без прямого поручения пользователя.

## Восстановление и данные

SQLite — источник завершённых результатов; Excel восстанавливается через `export`. Сохранённые проверки не оценивать повторно без новой версии/изменения CV. `backup` создаёт архив согласованных SQLite-снимков, без CV-бинарников. Команды и данные версий описаны в README. Никогда не коммитьте `data/`, ключи, карточки и реальные тестовые документы.

Для проверки повторяемости используйте `tools.audit_repeatability` по README:
сверка с книгой и повторы `preview` выполняются во временных копиях базы.
Новое прочтение сравнивайте отдельными аудиторскими карточками; сохраняйте
расхождения в отчёте, не подгоняйте баллы и не перезаписывайте прежние результаты.

Изменения критериев: `docs/criteria-and-banlists.md`. Перенос на Windows: `docs/restore-windows.md`.
Для архивной новой версии используйте `import-archive --criteria-dir /data/...` с полным набором источников; общий `scan` для архивного запуска запрещён.
