# Изменение критериев и бан-листов

Инструкция относится к новым версиям проверки. Перенос на другой компьютер не требует изменения критериев или повторной оценки.

## Источники и снимки

| Где | Что редактировать |
|---|---|
| `data/sources/clusters/*.xlsx` | Рабочая книга профессиональных требований, лист «Кого берём» |
| `data/sources/banlist/ФИО.csv`, `Компании.csv` | Рабочие запреты по личности и трудовой истории |
| `rules/accepted_rules.md` | Общие согласованные правила чтения и оценки, пользовательские дополнения |
| `data/state/runs/<run>/inputs/` | Замороженные источники конкретной версии; редактировать их нельзя |
| `inputs/amendments/rule262/` внутри версии | Проверенный реестр партнёров/резидентов и снимки официальных подтверждений |

Актуальный запуск указан в `data/state/active.json`; список версий показывает `docker compose run --rm app status --all`. Рабочие `data/sources` могут быть старше активного архивного запуска. Для изменения именно его критериев сначала скопируйте полный `inputs` в отдельную рабочую папку.

Книги и CSV с реальными данными остаются локально и входят в бэкап. В GitHub сохраняются код и общие инструкции. Реальные имена из персонального бан-листа в документацию и синтетические тесты не добавляются.

## Как подготовить изменение

1. Завершите текущие операции обработки. Создайте `backup` с новым именем и сохраните точную копию прежнего движка, если предстоит его изменение.
2. Кратко зафиксируйте изменение: требование, причина, дата, источник и согласование пользователя. Исправляйте рабочую копию, сохраняя прежний снимок.
3. В книге требований оставьте одну книгу в `clusters/`, лист «Кого берём», структуру колонок и номера строк. Читаются заполненные требования, а не только названия профилей. Не перемещайте строки без необходимости: номера входят в идентификаторы профилей и часть формализованных ограничений.
4. CSV сохраняйте в UTF-8, разделитель `;`. Сохраните заголовки, колонки и номера строк, включая пустые строки: движок содержит правила, связанные с номерами. В `Компании.csv` первая колонка — основание, вторая — срок, например `100%`, `Свободно`, `6 месяцев`. В `ФИО.csv` первые колонки — ФИО и телефон. Не объединяйте разные юридические лица по похожему названию.
5. Общие договорённости внесите в `rules/accepted_rules.md`. Если меняются расчёт, формальные ограничения, распознавание компаний или обработка сроков, одновременно измените движок и синтетические тесты: текст Markdown сам по себе не программирует новую формулу.
6. Создайте новую версию подходящей командой ниже. Проверьте `profiles`, источники, дату оценки и несколько контрольных карточек через `preview`. Оценки новой версии сохраняйте отдельно, старые результаты не перезаписывайте.

## Обычный запуск

Для запуска, созданного обычным сканированием, измените нужные файлы в `data/sources`, затем:

```powershell
docker compose build
docker compose run --rm app scan --new-version
docker compose run --rm app profiles
docker compose run --rm app status --all
```

Создаётся новая версия с текущей датой Москвы; полные тексты могут использоваться по хешу, профессиональные решения пересматриваются. Удаление отсутствующего файла не трактуется как удаление критерия: `scan` накладывает предоставленные источники на прежний набор. Для точной замены набора используйте архивный импорт с `--criteria-dir`.

## Отдельный архив

Для архивного запуска общий `scan`, включая `scan --new-version`, запрещён: он мог бы расширить состав кандидатов. Нужны исходный ZIP и исходная таблица из 38 колонок с ID в A. Возьмите их из отдельно сохранённых оригиналов; переносимый бэкап без CV не содержит ZIP.

Пример подготовки полной рабочей копии в PowerShell:

```powershell
$Run = (Get-Content -Raw -LiteralPath 'data/state/active.json' | ConvertFrom-Json).run
$Version = 'criteria-v2'
New-Item -ItemType Directory -Force -Path 'data/criteria' | Out-Null
if (Test-Path "data/criteria/$Version") { throw 'Выберите новое имя версии критериев' }
Copy-Item -LiteralPath "data/state/runs/$Run/inputs" -Destination "data/criteria/$Version" -Recurse
```

Отредактируйте копию. `--criteria-dir` принимает полный набор `clusters/`, обоих бан-листов и всех нужных дополнений. Он заменяет наследование целиком: пропущенный файл не подмешивается из прежнего запуска. Исходные таблицы верхнего уровня не используются как критерии; новый шаблон задаётся через `--template`. Общая политика берётся из текущего `rules/accepted_rules.md`.

После проверки нового реестра партнёров на выбранную дату:

```powershell
docker compose build
docker compose run --rm app import-archive --file /data/incoming/batch.zip --template /data/incoming/template.xlsx --criteria-dir /data/criteria/criteria-v2 --as-of 2026-11-12 --partner-registry /data/state/partner262/registry.json --output /data/exports/batch_criteria_v2.xlsx
docker compose run --rm app profiles
docker compose run --rm app extract --workers 2
```

Пути и дата в примере заменяются фактическими. Если переданный полный набор уже содержит проверенный реестр на ту же дату, `--partner-registry` можно опустить. Несовпадение дат блокирует импорт; менять дату в старом JSON без новой проверки нельзя.

Без `--criteria-dir` новый архив наследует набор активной версии, включая дополнения. Хеши архива, шаблона, эффективного набора критериев, движка и дата образуют ключ возобновления. Повтор неизменной команды продолжает тот же запуск; изменение правил создаёт другой запуск с пустыми оценками. Прежние карточки и баллы автоматически не копируются.

## Реестр официальных партнёров: amendment

Строка 262 охватывает всех официальных партнёров ОЭЗ «Алабуга», согласно уточнению пользователя. Подтверждайте конкретное юридическое лицо официальным источником; сохраняйте URL, выписку, дату проверки, исходный документ и SHA-256. Клиент, объект строительства или общее название не доказывают связь. Источник, проверенный позднее даты оценки, требует честного описания временной неопределённости.

Для уточнения реестра у существующего архивного запуска используйте `amend-archive`. Он сохраняет состав кандидатов, исходную таблицу и дату родителя. До изменения движка сохраните все его `.py` из `app/engine/` в локальный каталог, например `/data/state/parent_engine`. Это должен быть точный снимок движка родительской версии.

```powershell
docker compose run --rm app amend-archive --run PARENT_RUN --file /data/state/partner262/registry.json --engine-snapshot /data/state/parent_engine --output /data/exports/batch_amendment.xlsx
```

В дочерней версии факты и исходные баллы имеют явное происхождение, а результаты остаются незавершёнными до новых `preview`/`submit`. Подтверждения полного чтения не расширяются автоматически. Это специальный механизм уточнения реестра, а не команда произвольной замены всех профессиональных критериев. Полная схема реестра и порядок сохранения дочерних карточек приведены в разделе amendment в [README](../README.md).

## Контроль перед обработкой

Выполните синтетические тесты в Docker. Сравните контрольные карточки при неизменных фактах; расхождения нового прочтения фиксируйте отдельно. Передавайте исходные компонентные баллы: коэффициент «100 Лидеров» однократно применяет движок. После каждого кандидата — `submit`, после пакета — `export`. Старый запуск можно выбрать командой `use --run`, без повторной оценки его завершённых кандидатов.
