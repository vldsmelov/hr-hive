# Восстановление HR Hive на Windows

Нужны доступ к приватному GitHub-репозиторию, архив `.tar.gz`, его `.sha256` и паспорт переноса. Архив содержит персональные данные в текстах и результатах; передавайте его отдельно от GitHub. Оригиналы CV и их бинарные производные в этот комплект не входят.

## 1. Подготовить компьютер

Установите Git, GitHub CLI, Docker Desktop и VS Code. Запустите Docker Desktop с Linux-контейнерами и дождитесь готовности движка. Проверьте `git --version`, `gh --version`, `docker version`, `docker compose version`.

Установите расширение Codex в VS Code и войдите в свой аккаунт. Codex работает на Windows; настройки описаны в [официальной инструкции](https://learn.chatgpt.com/docs/windows/windows-sandbox). Авторизация Codex и GitHub выполняется заново на компьютере пользователя, учётные данные в бэкап не входят. Для проекта отдельный ключ модельного API не нужен.

Все следующие команды выполняются в PowerShell. Выберите локальную папку, например `C:\Projects`; рабочую SQLite не размещайте в сетевой или синхронизируемой папке. Все обращения к базам, включая проверки, выполняются через Docker.

```powershell
gh auth login
gh auth setup-git
New-Item -ItemType Directory -Force -Path C:\Projects | Out-Null
Set-Location C:\Projects
git clone https://github.com/vldsmelov/hr-hive.git
Set-Location hr-hive
New-Item -ItemType Directory -Force -Path data/backups | Out-Null
```

## 2. Перенести комплект и проверить SHA-256

Скопируйте архив, `.sha256` и внешний паспорт `.passport.json` в `data/backups`. При суффиксе времени используйте фактическое имя во всех командах. Проверка:

```powershell
$ArchiveName = 'hr-hive-transfer-2026-11-12.tar.gz'
$Archive = Join-Path 'data/backups' $ArchiveName
$Expected = ((Get-Content -Raw -Encoding UTF8 -LiteralPath "$Archive.sha256").Trim() -split '\s+')[0]
$Actual = (Get-FileHash -LiteralPath $Archive -Algorithm SHA256).Hash
if ($Actual -ne $Expected) { throw 'SHA-256 архива не совпадает; восстановление остановлено' }
$Passport = Get-Content -Raw -Encoding UTF8 -LiteralPath "$Archive.passport.json" | ConvertFrom-Json
git checkout --detach $Passport.code_commit
if ($LASTEXITCODE -ne 0) { throw 'Коммит из паспорта недоступен' }
docker compose build
if ($LASTEXITCODE -ne 0) { throw 'Сборка не выполнена' }
```

Коммит фиксируется намеренно: он соответствует критериям и движку сохранённых оценок. Обновление кода выполняйте отдельно после успешного переноса. Репозиторий сохраняет LF для исходников; исторические хеши CRLF поддерживаются проверкой движка.

## 3. Восстановить в пустое хранилище

До `restore` в `data/` допустимы только `backups/` и `cvs/`. Не запускайте `scan`, `extract` или другие команды подготовки данных. Если здесь уже есть рабочие данные, используйте отдельную папку проекта; не удаляйте их ради восстановления.

```powershell
docker compose run --rm app restore --file "/data/backups/$ArchiveName"
if ($LASTEXITCODE -ne 0) { throw 'Восстановление не выполнено' }
docker compose run --rm app doctor
if ($LASTEXITCODE -ne 0) { throw 'Окружение неполно' }
docker compose run --rm app status --all
if ($LASTEXITCODE -ne 0) { throw 'Не удалось прочитать состояние' }
docker compose run --rm --entrypoint python app -m tools.transfer_audit verify
if ($LASTEXITCODE -ne 0) { throw 'Состояние отличается от паспорта' }
docker compose run --rm app export
if ($LASTEXITCODE -ne 0) { throw 'Excel не восстановлен' }
```

`restore` проверяет размер и SHA-256 каждого файла до записи. `transfer_audit verify` сверяет активный запуск, даты, источники, файлы истории и выгрузок, целостность всех SQLite и логическое содержимое таблиц. Проверку выполняйте **до первого export**: новая выгрузка может изменить служебные сведения о ревизиях и сам файл Excel. Её штатное выполнение после успешной сверки допустимо.

Контроль последней пачки: `archive_20261104_100136_500602`, дата оценки **2026-11-04**, **281 ID**, из них **267 завершены и 14 незавершены с причинами ошибок**. Перенос не меняет эту дату на дату нового компьютера. Остальные запуски сверяются с паспортом; их количества не складываются как уникальные кандидаты.

Архив вручную поверх базы не распаковывайте. SQLite-файлы на Windows через Python/sqlite3 не открывайте. Общий `scan` после восстановления не нужен и для активного архивного запуска запрещён.

## 4. Продолжить работу и вернуть оригиналы

Откройте папку репозитория в VS Code. Пример первого сообщения:

> Прочитай AGENTS.md и rules/accepted_rules.md полностью. Выполни status --all. Сохрани прежние результаты, историю и даты оценок. Перед новой обработкой изучи полные критерии и бан-листы активной версии. Завершённые резюме повторно не оценивай.

Без CV доступны состояние, критерии, история, сохранённые тексты и восстановление Excel. Для повторного OCR и новых оценок отдельно перенесите оригиналы в `data/cvs`, сохранив относительную структуру из прежнего `data/cvs`. Например, файл, записанный в манифесте как `archive_RUN/folder/123.pdf`, должен лежать по адресу `data/cvs/archive_RUN/folder/123.pdf`.

Хеши и пути комплектов сохранены в `archive_manifest.json` каждого архивного запуска и в базе. Перед продолжением координатор сверяет оригиналы по SHA-256 с манифестом **в Docker**. Простое совпадение имени не подтверждает тот же документ. Для обычных запусков сохранённые пути и хеши берутся из поля `files` SQLite, также только через контейнер. После возврата файлов используйте `retry --ids ...` только для выбранных незавершённых ID и дождитесь окончания извлечения. Блокировка обрезанного или конфликтного исходника сохраняется до предоставления корректного комплекта; повторный OCR того же файла её не снимает.

Новый ZIP импортируйте отдельной командой `import-archive`, не расширяя старый запуск. Изменения правил описаны в [инструкции по критериям](criteria-and-banlists.md).

## Состав бэкапа и новый комплект переноса

Включены все версии и история, тексты, карточки, базы, исходные книги, результаты, критерии и их доказательства. В SQLite-снимках очищаются только бинарные CV в `source_files`; исходные рабочие базы не меняются. Изображения и конвертированные копии CV, старые архивы и временные файлы исключены. Содержимое `sources/` и замороженных `inputs/` сохраняется как источник правил.

Если официальное доказательство находится вне этих каталогов, координатор добавляет точный путь относительно `data/`, SHA-256 и `role: "rule_evidence"` в `data/state/backup_evidence.json`. Пример записи:

```json
{"files":[{"path":"state/audit/organization/official.pdf","sha256":"SHA256_ФАЙЛА","role":"rule_evidence"}]}
```

Это список отдельных проверенных документов, не каталогов с CV. Несовпадение хеша блокирует бэкап. Манифест архива перечисляет включённые файлы, исключённые производные и причины исключения. Тексты CV и результаты остаются в архиве, даже когда оригиналы исключены.

В комплекте от 12.11.2026 отдельно зарегистрирована старая повреждённая диагностическая копия `state/recovery_before_continuation/state.sqlite`. Она остаётся на исходном компьютере и исключается по точному пути и SHA-256 через `state/backup_exclusions.json`; причина присутствует в манифесте. Рабочие базы и исторические версии этим механизмом исключать запрещено.

Для нового комплекта остановите обработку и используйте новое имя:

```powershell
$Commit = git rev-parse HEAD
docker compose run --rm --entrypoint python app -m tools.transfer_audit capture --commit $Commit
if ($LASTEXITCODE -ne 0) { throw 'Не удалось создать паспорт' }
docker compose run --rm app backup --output /data/backups/hr-hive-transfer-NEW.tar.gz
if ($LASTEXITCODE -ne 0) { throw 'Бэкап не создан' }
Copy-Item -LiteralPath data/state/transfer_passport.json -Destination data/backups/hr-hive-transfer-NEW.tar.gz.passport.json
```

Паспорт сначала сохраняется внутри переносимого состояния, затем копируется рядом с готовым архивом для выбора коммита до восстановления. Архив проверяется пробным восстановлением в отдельное пустое хранилище. На исходном компьютере прежние результаты и CV сохраняются.
